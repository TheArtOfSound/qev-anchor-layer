Protocol overview

How QAL works

QEV encrypts on your machine. The chain stores a compact commitment about that encrypted vault — not the payload.

Non-negotiable boundary

QEV does not run on-chain. Putting the vault on-chain would be expensive, permanent, and pointless. QAL anchors digests and registry state only.

Pipeline

artifact
  → local QEV encryption (Argon2id + XChaCha20-Poly1305)
  → canonical vault JSON
  → SHA-256 digest
  → optional encrypted storage (IPFS/local)
  → Solana anchor
  → portable receipt

Verify

supplied vault
  → validate schema
  → canonicalize + SHA-256
  → read Solana anchor (receipt-directed)
  → compare digests
  → report match AND endorsement separately

CLI (after build)

pnpm install && pnpm build
pnpm doctor
qal encrypt evidence.json --out evidence.qev
qal anchor evidence.qev --network devnet
qal verify evidence.qev --receipt evidence.qal-receipt.json

What QAL proves

Does

This exact QEV vault bytestring existed and was committed by a signing wallet, with later endorsement status.

Does not

Real-world authorship, legal notarization, plaintext truth, or that revocation erases copies already decrypted.
