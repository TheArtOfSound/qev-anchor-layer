The problem in one minute

Anyone can post a screenshot, a “locked LP,” a roadmap PDF, or a “team doxx vault” on a website. Websites can be edited. Telegram can lie. Screenshots can be faked.

What people actually need is: can I check, myself, that this exact sealed package is the same one someone committed earlier?

That’s what we’re building. Two pieces:

  • QEV — encrypts the file on your computer (already works offline).
  • QAL — puts a tiny fingerprint of that sealed file on Solana, so others can re-check it.

Walkthrough (plain English)

  1. You have something sensitive

    A team statement, a vesting schedule, a partnership note, dump of build hashes, a “we won’t rug” letter, whatever. You do not want the whole world reading it raw forever — but you may want to prove later that this sealed version is the one you published.

  2. Encrypt it locally with QEV

    On your machine (or with the QEV app/CLI), lock the file with a long phrase. You get a .qev vault: scrambled data + metadata. No chain yet. If someone never gets the phrase, they can’t read it.

  3. Make a fingerprint (digest)

    QAL takes the full vault JSON, sorts it the same way every time, and runs SHA-256. Result: a 64-character hex fingerprint. Change one byte of the vault → fingerprint changes. Formatting noise does not.

  4. Anchor the fingerprint on Solana

    A wallet you control signs a transaction that stores: the fingerprint, who issued it, and a status (active / revoked / replaced). Not the password. Not the file. Not the keys.

  5. You keep a small receipt

    A JSON receipt points at the on-chain record (addresses, network, tx). Share the vault + receipt with people who should be able to check. They don’t have to trust your website.

  6. Anyone verifies independently

    Recompute the fingerprint from the vault file. Read the Solana account. Same hash? → package matches. Status still active, or revoked / superseded? → separate answer. Match and status are never collapsed into one vague “OK.” 

file
  → QEV encrypt (local)
  → fingerprint SHA-256
  → Solana stores fingerprint + status
  → others re-hash + read chain

What “safer” means here (especially for memecoins)

Memecoins are not made “safe” by any tool. They can still go to zero. Rugs still happen. What QAL can improve is honesty about sealed statements:

  • Team can lock a disclosure vault before hype peaks and prove the sealed blob didn’t change later.
  • If they need to update the story, they supersede with a new vault and leave a public trail — not silent website edits.
  • If a promise is withdrawn, they can revoke the endorsement without erasing history (people still see it was once anchored).
  • Community can verify with their own tools — not “trust our dashboard.”

What this is not

  • Not on-chain encryption (secrets never go on Solana)
  • Not a guarantee the team is honest or human
  • Not proof of real-world identity just because a wallet signed
  • Not a memecoin, not a launchpad, not a token
  • Not production-ready or audited yet
