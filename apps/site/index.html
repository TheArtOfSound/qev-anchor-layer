QEV Anchor Layer

Encrypt a file with QEV on your machine. Commit a SHA-256 of that vault to Solana. Anyone can recompute the hash and check the chain.

Pre-alpha. Unaudited. Not for production evidence or legal claims. There is no token.

The idea

QEV already does local encryption (Argon2id + XChaCha20-Poly1305). QAL does not reimplement that. It only records that a specific encrypted envelope existed, who signed the anchor, and whether that endorsement was later revoked or superseded.

The vault itself stays off-chain. On-chain state is digests, pubkeys, and status — not plaintext, phrases, or keys.

Flow

file → QEV encrypt → canonical JSON → SHA-256 → Solana record → receipt

verify: recompute digest → read account → match? → status?

On-chain

Stored

Vault digest, schema hash, issuer, controller, status, optional parent claim.

Never stored

Plaintext, passphrase, derived keys, content keys, private material.
